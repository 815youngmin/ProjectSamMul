# ProjectSamMul

서버 없이 로컬에서 실행되는 2D 서바이버류 액션 게임 데모입니다.
이전에 참여했던 모바일 게임 프로젝트에서 **제가 직접 작성한 클라이언트 코드**만 추려내고,
서버·네트워크·유료 에셋·회사 자산에 의존하던 부분은 새로 작성한 오프라인 구현으로 대체했습니다.

**▶ [웹에서 바로 플레이하기](https://815youngmin.github.io/ProjectSamMul/)** (PC 브라우저 권장, 설치 불필요. WebGL 빌드를 GitHub Pages로 제공합니다)

> 코드를 처음 보는 분은 [docs/architecture.md](docs/architecture.md)부터 읽으면 전체 구조를 10분 안에 파악할 수 있습니다.

## 작업 방식

이 저장소는 이전 프로젝트의 코드를 **Claude Code(Anthropic)** 의 도움을 받아 옮기고 정리했습니다.
역할은 다음과 같이 나뉩니다.

- **원본 게임플레이 코드** (스테이지, 캐릭터/몬스터 AI, 스킬, 장판, 전투/스탯, 스테이지 이벤트, UI 로직): 제가 이전 프로젝트에서 직접 작성한 코드입니다. 파일 단위로 작성 여부를 확인해 제가 쓴 것만 가져왔습니다. 데모에서 실행되지 않는 이전 테마의 보스·몬스터 코드도 작성한 코드를 보여 주기 위해 그대로 두었습니다.
- **Claude Code와 함께 진행한 작업**: 이관 범위 분석, 회사 자산·서버 의존 코드 제거, 오프라인 세션·`Shared` 데이터 계층·플레이스홀더 애니메이터/리소스 같은 대체 구현 작성, 미사용 코드 정리, 데모용 정적 데이터 작성, 공용 공격 비주얼과 판정 범위 표시, 원본 보스 액션을 참고한 데모 보스 6종의 전용 AI·액션 구성, 밸런스 조정, 옵션 팝업, WebGL 배포, 문서 작성.

## 데모 내용

로비(챕터 · 캐릭터 · 장비를 한 줄씩 라디오 버튼으로 선택, 옵션) → 스테이지 플레이 (5분간 웨이브 생존, 엘리트, 중간 보스와 최종 보스) → 결과 팝업

| 항목 | 내용 |
|---|---|
| 챕터 | 3개 (원시 시대 / 빙하기 / 미라의 무덤), 각 5분. 원본 1~3챕터의 스폰 시간표를 5분으로 줄이고 수치를 데모에 맞게 조정 |
| 캐릭터 | Tenti, Ignatia, Dice. 각자 고유 기본 공격 스킬 |
| 장비 | 세트 3종 (갑옷 + 장갑, D / B / S 등급). 체력 +564 / 750 / 1000, 공격력 +20 / 30 / 40 및 +30 / 40 / 50%, 이동속도 +0 / 15 / 30% |
| 스킬 | 16종 (액티브 11, 패시브 5). 레벨업 시 3택1 선택, 스킬 상자, 5레벨 초과 시 초월 |
| 몬스터 | 일반·엘리트 25종, AI 전략 8종 (근접, 원거리, 돌진, 통과, 독장판, 소환, 반사탄, 사망 폭발) |
| 보스 | 6종 (챕터마다 중간 보스와 최종 보스). 보스마다 전용 AI 전략이 있고, 2~4개의 전용 액션 중 하나를 무작위로 골라 사용 |
| 보스 액션 | 돌진, 부채꼴 투사체, 유도 오브젝트, 나선 이동 장판, 벽에 튕기는 반사 오브젝트, 돌진 중 원형 탄막, 엘리트·몬스터 소환, 분열 오브젝트, 맵 밖에서 가로지르는 돌진, 다중 장판 |
| 시스템 | 경험치·레벨, 아이템 상자(체력·자석·폭탄·골드·스킬 상자), 부활 1회, 일시정지, 결과 팝업, 배속(x1.0 / x1.5 / x2.0, 클리어한 챕터에서 사용 가능) |
| 옵션 | 언어 전환(한국어 / 영어), 음소거, 배경음·효과음 볼륨. 바꾸는 즉시 적용되고 저장됨 |
| 그래픽 | 몬스터·보스·캐릭터·아이템은 AI 생성 스프라이트. 공격 판정 범위는 도형으로 표시(플레이어 파란색, 적 빨간색). 일부 연출은 플레이스홀더(흰 사각형) |
| 사운드 | 로비·전투 배경음 2곡과 효과음. 효과음은 프리팹마다 개별 음량 배율을 가짐 |

## 실행 방법

1. Unity **2021.3.45f2** 로 프로젝트를 엽니다.
2. Asset Store에서 **DOTween Pro**를 임포트하고 (`Assets/Plugins/Demigiant`), DOTween Utility Panel의 Setup에서 TextMeshPro 모듈을 켭니다. TextMeshPro 텍스트 트윈(`DOCounter`)을 쓰기 때문에 무료 버전만으로는 컴파일되지 않습니다. 저장소에는 포함되어 있지 않습니다.
   게임 코드가 어셈블리 정의(`Assets/Scripts/SamMul.asmdef`)로 묶여 있으므로, 같은 패널에서 **Create ASMDEF**도 눌러 DOTween 쪽 어셈블리 정의(`DOTween.Modules`, `DOTweenPro.Scripts`)를 만들어야 합니다.
3. 메뉴 **Demo → Validate Static Data** 로 데이터 로드를 확인합니다.
4. `Assets/Scenes/Lobby.unity` 를 열고 Play.

씬·한글 폰트·사운드 프리팹·옵션 팝업 프리팹은 저장소에 포함되어 있습니다. 다시 만들어야 할 때만 **Demo → Build Scenes / Build Korean Font / Build Sound Prefabs / Build Option Popup Prefab** 메뉴를 사용합니다.

### 웹 빌드

웹 버전은 WebGL로 빌드한 결과물을 `gh-pages` 브랜치에 올려 GitHub Pages로 제공합니다. GitHub Pages는 압축 파일용 응답 헤더를 보내지 않으므로 Player Settings의 **Decompression Fallback**을 켠 상태로 빌드합니다. `main` 브랜치에는 빌드 산출물을 넣지 않습니다.

## 테스트

**Unity Test Framework 1.1.33** (NUnit 기반)으로 작성했고, `Window > General > Test Runner`에서 실행합니다. 총 26개(EditMode 13, PlayMode 13)입니다.

### 구성

테스트가 게임 코드를 참조할 수 있도록 게임 코드를 어셈블리 정의로 묶고, 테스트는 별도 어셈블리로 분리했습니다. 테스트 어셈블리는 빌드에 포함되지 않습니다.

| 어셈블리 | 위치 | 역할 |
|---|---|---|
| `SamMul` | `Assets/Scripts` | 게임 코드 |
| `SamMul.Tests.EditMode` | `Assets/Tests/EditMode` | 플레이하지 않고 데이터·에셋을 검사 (에디터 전용) |
| `SamMul.Tests.PlayMode` | `Assets/Tests/PlayMode` | 실제 씬을 띄워 게임을 진행시키며 검사 |

### EditMode — 데이터와 텍스트 검증

| 테스트 | 내용 |
|---|---|
| `StaticDataTests` | 챕터·스테이지·이벤트 구성, 스폰 이벤트의 몬스터 참조와 스탯 가중치, 스테이지별 보스 2종과 경고, 몬스터 데이터의 리소스 경로에 실제 파일이 있는지, 한·영 키 집합 일치 |
| `LocalizationTests` | 코드·씬·프리팹·정적 데이터가 쓰는 텍스트 키가 한·영 양쪽에 있는지, 자리표시자 일치, 없는 키 요청 시 동작 |

텍스트 키는 네 곳에서 모읍니다: 코드의 `GetText(` 호출, 씬과 프리팹에 붙은 `LocalizedText` 컴포넌트의 직렬화 값, 정적 데이터 JSON 의 `*Key` 필드.

### PlayMode — 실제 플레이 검증

| 테스트 | 내용 |
|---|---|
| `PlayFlowTests` | 로비 초기화, 챕터별 로비 → 스테이지 → 로비 전환 |
| `BossPatternTests` | 보스 6종의 전용 액션을 하나씩 실행해 시작과 종료(대기 상태 복귀) 확인 |
| `MonsterSpawnTests` | 챕터별로 몬스터 종류마다 첫 등장 시각으로 스테이지 타이머를 옮겨 실제로 스폰되는지 확인 |

- **실패 기준**: 대기 조건이 실제 시간 30초 안에 충족되지 않거나, 진행 중 예외·에러 로그가 하나라도 나오면 실패합니다.
- **진행 방식**: 로비의 시작 버튼과 같은 데이터로 스테이지에 들어가 4배속으로 진행합니다. 플레이어 체력은 99999로 올려 도중에 죽지 않게 하고, 레벨업 팝업은 첫 번째 후보를 자동 선택합니다.
- **보스전 처리**: 보스전 중에는 스테이지 타이머가 멈추므로, 스폰 테스트는 보스가 등장하면 바로 처치하고 다음 시각으로 넘어갑니다.

### 설계 원칙

- **게임 코드에 테스트용 분기를 넣지 않습니다.** 테스트가 게임을 조작하는 코드(씬 이동, 배속, 체력, 타이머 이동, 보스 처치)는 `StageTestDriver` 한 파일에 모았습니다.
- **비공개 멤버는 `StageTestDriver` 안에서만 리플렉션으로 접근합니다.** 멤버 이름은 상수로 선언해 두어, 게임 쪽 이름이 바뀌면 그 상수만 고치면 됩니다.

### 한계

- 리소스가 없으면 플레이스홀더로 대체되고 경고 로그만 남으므로, 플레이 테스트는 리소스 누락을 잡지 못합니다. 그래서 몬스터 데이터의 리소스 경로는 파일 존재를 따로 검사합니다. 스킬·장판·UI 등 그 밖의 리소스 누락은 아직 잡지 못합니다. (사운드 프리팹 누락은 예외라서 잡힙니다.)
- 플레이어 스킬 동작과 챕터 클리어까지의 전체 플레이는 아직 테스트하지 않습니다.
- PlayMode 테스트는 로비 초기화를 거치므로 로컬 세이브의 캐릭터·장비 선택이 첫 번째 항목으로 바뀝니다.

## 설계 메모

- **오프라인 세션**: 원래 서버 프로토콜(챕터 입장/종료/포기/부활)을 같은 호출 형태로 로컬에서 즉시 처리하고 JSON으로 저장합니다.
- **플레이스홀더 리소스**: `ResourcePool` 이 프리팹/스프라이트/스켈레톤 데이터가 없을 때 요청된 컴포넌트를 붙인 오브젝트를 만들고, 직렬화 참조 필드를 리플렉션으로 채워 NullReference 없이 동작하게 합니다. 사운드만 예외로, 없으면 즉시 예외를 던집니다.
- **정적 데이터**: 테이블별 JSON 파일을 Newtonsoft로 읽으며, 없는 테이블은 빈 테이블로 취급합니다.
- **보스 AI**: 보스는 `BossIdleAIStrategy` / `BossCombatAIStrategy`를 상속한 전용 전략을 가지며, 전략이 가진 액션 목록에서 하나를 골라 실행합니다. 액션은 `SmartAction`의 서브 액션 시간표(예고 → 공격 → 후딜)로 작성합니다.
- **공격 판정 표시**: 전용 이펙트가 없는 스킬은 실제 판정 도형(원·사각·부채꼴)을 `AttackAreaFlashManager` 로 그려 범위를 그대로 보여 줍니다.

## 라이선스

이 저장소의 코드는 포트폴리오 목적으로 공개합니다. 제3자 에셋(DOTween 등)은 각자의 라이선스를 따르며 저장소에 포함하지 않습니다.

로비 아이콘, 몬스터·캐릭터·아이템 스프라이트, BGM 같은 데모용 이미지·음악은 AI 생성 리소스입니다.
한글 서체는 넥슨 메이플스토리 서체를 사용합니다 (`Assets/Fonts/LICENSE-Maplestory.md`).
